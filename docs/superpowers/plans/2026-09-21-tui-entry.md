# seeing-tui 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 新增独立 TUI 入口 `seeing-tui`，对齐 WebUI 会话聊天能力（内联流式、工具卡、Markdown、权限/问答内联、子代理进度、会话与模型切换）。

**Architecture:** 薄 Host Shape 包 `src/hosting/Seeing.Agent.Hosting.Tui`（仅接线，镜像 `Hosting.Web`）+ 可执行 sample `samples/Seeing.Agent.Tui`（组合根 + 全部 UI/引擎）。复用 `IChatOrchestrator` / `IExecutionEventPublisher` / `IPermissionRequestManager` / `IQuestionRequestManager` / `SessionData` 服务端投影；TUI 只读快照 + 消费增量事件。

**Tech Stack:** .NET 10、Spectre.Console 0.57.2、Markdig 1.4.0、System.CommandLine 2.0.11、xUnit + FluentAssertions + Moq。

**Spec:** `docs/superpowers/specs/2026-09-21-tui-entry-design.md`（v2.2，双审通过）

### 1.3 事件解释器（纯逻辑，可单测）

```csharp
namespace Seeing.Agent.Tui.Services;

public sealed class TuiEventInterpreter
{
    public TuiEventInterpreter(TuiViewState state);
    public bool Apply(IMessageEvent evt);   // 返回是否引起视图态变化
    public bool IsExecuting { get; }
}
```

**必须实现的规则（权威见 spec §6.1/§6.2）**：
- 按 Key 幂等 upsert；`Assistant` Key=`{loopId}_step{step}`，`Tool` Key=`tool:{callId}`。
- 维护 `_seenStreamStart: HashSet<(string? loopId,int step)>`：`StreamStart` 加入并**重置**该 step 缓冲；`StreamDelta` **仅当 key ∈ `_seenStreamStart`** 才累加，否则**丢弃**（长流式半途回放保护）。
- `StreamComplete` 用完整 `ChatMessage` **整体覆盖**该 step。
- `ExecutionStartedEvent`（`loop.start` 且是 ExecutionStartedEvent）→ 记 `ActiveExecutionId`；`ExecutionCompleteEvent`（`loop.complete` 且 ExecutionId 匹配）→ 清执行态。二者与 `LoopStartEvent`/`LoopCompleteEvent` 按具体类型区分，不按 `Type` 字符串。
- `ToolCallEvent` 按 `CallId` upsert，`Status` 映射、`Output/Error/Title`、`task` 解析 `TaskId`（metadata `task_id` 或结果前缀）。
- `TodoUpdateEvent` 整体替换；`BudgetStatusEvent/BudgetWarningEvent`（`Seeing.Agent.TokenBudget.Events`）更新 `Budget`。
- `LoopCancelled`/`Error`/`LlmRetry`/`CommandResult`/`SessionTitleChanged`/`ModeUpdate`/`Compaction*` 按 spec §6.2 表处理。
- 非回合类事件始终处理。
