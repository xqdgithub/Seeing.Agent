# WebUI 主页改版：品牌细条 + 控制台分区

- 日期：2026-11-06
- 状态：待批准（批准后进入实现计划）
- 范围：`samples/Seeing.Agent.WebUI`（`Pages/Index.razor` 为主，少量服务/样式接线）
- 前序：`2026-10-31-webui-home-dashboard-design.md`（本次替换其 §4 的布局结论）

## 1. 意图与为什么

现状主页（2026-10-31 版）是三段式：hero（40px 字标 + 标语 + 说明 + 两个按钮）→「总览」小节标题 → 四张等尺寸卡片。
用户反馈两个具体问题：

1. **头重脚轻**：hero 只有几行小字，视觉重量撑不住整页，占比却很大。
2. **中间一条贯穿的卡片，下面大片空白**：`.home-board` 用 `grid-auto-rows: 148px` 固定行高，内容到底就断；而页面挂在 `content-area`（`height:100vh; overflow:hidden`）里，剩余 40% 视口永远空着，且无法靠滚动消解。

用户已明确方向：**控制台**（信息密度高、扫一眼知道有什么），但**不做完全铺满**，上方要保留品牌信息。

目标：把首页变成「品牌细条 + 连续分区控制台」——顶部一条 88px 品牌带交代身份与主操作，
下方三栏分区按视口剩余高度分配，每寸都是内容，不溢出、不留死白。

## 2. 目标 / 非目标

目标：

- 品牌区压缩为**一条 88px 细条**（字标居左），既保留品牌又不头重脚轻；
- 下方用**连续分区 + 1px 分隔线**替代「卡片 + 间距」，消除「一条卡带」观感；
- 三栏按视口高度用 `fr` 分配，列内独立裁切/滚动，**首屏无死白、无溢出**；
- 每块内容量给足（会话 12–14 行、执行记录按剩余高度铺满）；
- 数据全部来自现有服务，不新增后端接口。

非目标：

- 不做轮询/实时订阅（沿用「首屏快照 + 刷新 + 返回重载」）；
- 不改侧边栏导航结构、不改模块路由；
- 不引入图表库（24 小时时间轴仍用 flex 格子自绘）；
- 不做深色模式专项适配（沿用现有主题变量）。

反目标（做到也不算成功）：

- 变成「四张卡换了个排列」——分区之间必须靠细线而非卡片边框建立结构；
- 为了铺满而塞入无信息量的占位内容（空标签、装饰性数字）；
- 品牌区又长回 hero（>120px）导致下面内容被压成一条。

## 3. 方案选择（Approaches）

已用浏览器摆三版对照草稿（`.superpowers/brainstorm/home-console-v1~v3.html`），
差异集中在两处：**骨架形态**（v1 三栏 / v2 上下两段 / v3 两列主从）与**品牌区高度**（88 / 132 / 210px）。

最终选定组合：**V1 三栏工作台骨架 + A 品牌细条 88px**。

| 方案 | 取舍 |
|---|---|
| **V1 + A（已选）** | 三栏各司其职、密度最高；88px 细条腾出最多内容空间，品牌靠字标本身承载 |
| V2 上下两段 + A | 时间轴主图更突出，但下半四块平分后会话只剩 8 行 |
| V3 两列主从 + A | 会话列最显眼，但右列塞四段后每段都偏薄 |
| V1 + B（居中 132px） | 品牌仪式感更好，代价是每栏少一行 |
| V1 + C（展开 210px） | 品牌最足，但下面是「一条」——退回用户最初否定的形态 |

选 A 的理由：用户要「控制台」，输入是密度；88px 已足够放下字标 + 标语 + 三枚数字 + 两个按钮，
品牌信息一项不少，只是从「纵向堆叠」改为「横向排列」。这正是不头重脚轻的做法。

## 4. 布局规格

### 4.1 整体骨架

```
┌──────────────────────────────────────────────────────────────────────┐
│ [字标 34px] │ 标语 / 说明          会话20 任务2 待办3 │ 新建 · 继续    │ 88px 固定
├────────────────────┬───────────────────────────────┬─────────────────┤
│ 最近会话（12–14 行）│ 定时任务 · 今日（24h 时间轴）  │ 运行状态         │
│  …flex 1 裁切…      │ 待触发（1 行）                │  ─── hair ───   │
│ ──── hair ────     │ 今日已执行（flex 1 裁切）      │ MCP 服务器       │
│ 待我处理（固定 2 行）│                               │  ─── hair ───   │
│                    │                               │ 智能体           │
│                    │                               │  ──── flex ────  │
│                    │                               │ 技能·工具·模型   │
└────────────────────┴───────────────────────────────┴─────────────────┘
        300px                    1fr (min 0)                  230px
```

- 容器：`height:100%; display:flex; flex-direction:column; overflow:hidden;`
- 主体：`flex:1; min-height:0; display:grid; grid-template-columns:300px minmax(0,1fr) 230px;`
- 分隔线：格线用 `gap:1px` + 容器底色 `#e7eaee` 模拟 1px 发丝线，不用卡片边框、不用圆角、不用阴影。
- 列内：`display:flex; flex-direction:column; min-height:0;`，填充区 `flex:1; min-height:0; overflow:hidden;`。
  首屏不滚动整页；内容超出时在填充区内裁切（与现状 `dash-card` 的 `overflow:hidden` 口径一致）。

### 4.2 品牌细条（88px）

| 位置 | 内容 |
|---|---|
| 左 | `seeing-wordmark.png` 高 34px（现有资源，`Pages/Index.razor` 已在用） |
| 竖线 | 1px `#e7eaee`，高 30px |
| 中 | 标语「行到水穷处，坐看云起时」（12px）+ 说明「会话、定时任务与待办一屏总览」（10.5px，`#a0a8b4`） |
| 右（靠右） | `会话 20 · 任务 2 · 待办 3` 三枚数字，标签 10.5px 灰、数字 13px 深色；待办用 `#c47f17` |
| 竖线 | 同上 |
| 最右 | 主按钮「继续上次会话」（主色实心）+ 次按钮「新建会话」（描边） |

去掉：大字标语段、独立说明段、居中的两个大按钮、以及「总览」小节标题 + 右侧刷新按钮。

### 4.3 三栏内容

**左栏 · 最近会话**
- 头：`最近会话`（区域标题）+ 右上「全部 →」跳 `/sessions`；
- 主体：12–14 行，每行「标题 + 相对时间」，行 hover 底色 `#f7f9fb`，点击进 `/session/{id}`；
- 底部固定：`待我处理`（待审批 N / 待回答 N），**仅当任一非零时出现**（沿用 `HasActionItems`）；整块点击打开审批中心抽屉。

**中栏 · 定时任务 · 今日**
- 头：「定时任务 · 今日」+「全部 →」跳 `/cron-jobs`；
- 24 小时时间轴：24 个 flex 格，有任务的整格高亮（已过压暗、当前小时描主色边），`00/06/12/18/24` 刻度；
- 待触发：一行「下次：{任务名} + MM-dd HH:mm」；
- 今日已执行：`flex:1` 撑满剩余高度并裁切，行显示「任务名 + HH:mm · 耗时」，失败行状态标红。

**右栏 · 运行状态**
- 调度器：`运行中 / 已停止 / 待机` + 线程池 + 下次触发时间；
- MCP 服务器：逐条列出名称 + 连接状态点（已连接绿 / 错误红 / 其他灰）；
- 智能体：逐条列出名称 + `Native`/`ACP`；
- 底部固定：`技能 27 · 工具 58 · 模型 4`（承接原「概览」卡中被移出品牌区的四项）。

数字分布说明：原「概览」7 项 → 会话/任务/待办进品牌条（3 项），技能/工具/模型进右栏底部（3 项），
剩余「智能体 4」由右栏智能体列表条数自然体现，不再单列。

### 4.4 响应式

| 断点 | 行为 |
|---|---|
| >1280px | 三栏（300 / 1fr / 230） |
| 1024–1280px | 三栏，左栏降到 260px、右栏降到 200px |
| 768–1024px | 右栏隐藏（其数据在对应页面可查），左栏 + 中栏两栏 |
| <768px | 单列，允许整页纵向滚动（`overflow-y:auto`），品牌细条改为两行（字标一行、数字与按钮一行） |

### 4.5 状态

- **加载中**：仅主体区显示 `Skeleton`，品牌条常驻（不整页 Spin）；
- **空态**：会话为空 → 左栏「还没有会话」+ 新建按钮；今日无任务 → 中栏「今天没有定时任务」+ 下次触发；
  右栏无 MCP → 该段整块隐藏；
- **错误**：`_error` 非空时在品牌条下方插入一行 `Alert`（不遮挡主体，主体仍渲染已有数据）。

## 5. 数据来源

| 区块 | 来源 | 变化 |
|---|---|---|
| 最近会话 / 会话数 | `ISessionDirectory.ListSummariesAsync()` | 取数从 `RecentSessionCount = 3` 改为 14 |
| 待审批 / 待回答 | `PermissionInbox.TotalCount` / `QuestionInbox.TotalCount` | 复用 |
| 今日时间轴 / 待触发 | `SchedulerStatusService` + `IScheduleManager.ListJobsAsync()` + `HomeDashboardView.TodayRuns/NextRunAfter` | 复用 |
| 今日已执行 | `IScheduleRepository.GetHistoryAsync` + `HomeDashboardView.TodayExecutions` | 复用 |
| 调度器状态 | `SchedulerStatusService.GetStatusAsync()` | **现已被调用但结果未使用**，本次接上（运行中/线程池/下次触发） |
| MCP 服务器 | `McpStateService.GetCachedStatus()` | 新增使用（现有 Singleton 缓存，1s 刷新） |
| 智能体列表 | `IAgentRegistry.GetPrimaryAgentsAsync()` | 复用（已取，本次展示名称 + `Runtime`） |
| 技能/工具/模型 | `ISkillCatalog.EnabledEntries.Count` / `IToolManager.GetRegisteredTools().Count` / `ILlmService.GetAvailableModels().Count` | 复用 |

不新增任何后端接口，不新增服务类。

## 6. 我的判断（可推翻）

1. **去掉「总览」小节标题与刷新按钮**：分区标题已承担导航，刷新按钮在控制台里是低频操作；
   数据在返回页面时自动重载（沿用现状）。若确需手动刷新，退回加在品牌条最右一枚图标按钮。
2. **「待我处理」留在左栏底部而不是独立分区**：它在多数时刻为零，独立分区会形成常年空块；
   挂在会话列表底部，非零时才出现，零成本。
3. **品牌条用横向排列而非居中堆叠**：居中会立刻回到 hero 的形态；横向排列让 88px 成为「表头」而不是「封面」。
4. **不引入「实时活动流」区块**：它最能填充空白，但需要订阅会话事件流，超出本次范围；
   若日后要做，位置预留在中栏「待触发」与「今日已执行」之间。
5. **右栏在 768–1024px 直接隐藏而非折叠**：折叠交互增加状态复杂度，其数据在 `SchedulerPage` / `McpPage` / `AgentsPage` 均可查。

## 8. 验证

- `dotnet build Seeing.Agent.slnx` 通过；
- `dotnet build tests/apps/Seeing.Agent.WebUI.Tests` + `dotnet vstest ...` 全绿；
- 手动在 ≥1280 / 1024–1280 / 768–1024 / <768 四档宽度检查：
  无整页滚动条（<768 除外）、无横向溢出、列内裁切正常、品牌条不换行错位；
- 逐入口校验：字标（无跳转）、待办块 → 审批抽屉、会话行 → `/session/{id}`、
  「全部 →」→ 对应列表页、任务执行行 → `/cron-jobs/{jobId}`；
- 空数据场景：无会话 / 无定时任务 / 无 MCP 各跑一次，确认空态文案与不塌陷；
- 键盘可达：会话行与「全部 →」可 Tab 聚焦并有可见焦点环（沿用现状 `focus-visible` 口径）。
